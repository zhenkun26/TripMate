## Purpose

提供行程地图展示能力：由后端基于行程景点坐标生成静态地图图片（含全局编号、按天配色与跨天路线连接），前端以图片标签展示，高德 Key 不落地。

## ADDED Requirements

### Requirement: 后端生成静态地图图片
系统 SHALL 在行程生成后，由后端调用高德静态图 API 生成 PNG 图片，并以不透明 token 形式返回 map_image_url；前端不得接触高德 Key。

#### Scenario: 行程返回地图图片地址
- **WHEN** 行程生成完成且景点坐标可用
- **THEN** TripPlan 返回 map_image_url（指向后端代理端点），前端可直接以图片标签渲染

### Requirement: 地图包含完整行程信息
静态地图 SHALL 标注全部景点（全局顺序编号、按天配色）以及跨天路线连接线；酒店信息保留在每日行程中，不在地图上标注。

#### Scenario: 三天行程地图
- **WHEN** 行程含 3 天、共 7 个景点与 3 家酒店
- **THEN** 地图显示编号 1-7 的景点标记（按天分色）与跨天连接线，酒店信息仅在每日行程中展示

### Requirement: 图片缓存与防篡改
地图代理端点 SHALL 基于不透明 token 取参，拒绝篡改参数；同一行程重复请求 SHALL 命中图片缓存，不重复调用高德。

#### Scenario: 重复请求命中缓存
- **WHEN** 同一行程第二次请求静态图
- **THEN** 返回缓存的图片，不产生新的高德静态图调用

### Requirement: 失败容错
静态图生成失败时，系统 SHALL 返回空的 map_image_url 并隐藏地图区块，行程其余内容正常展示。

#### Scenario: 静态图服务不可用
- **WHEN** 高德静态图 API 调用失败
- **THEN** 前端隐藏地图区块，概览、每日行程与天气正常展示
